# Orbit Notes — build and install on a Pixel 10 (phone-only)

This repository contains the v0.12 Android-only Orbit Notes prototype and a GitHub Actions workflow at `.github/workflows/android-apk.yml`.

## Before you start

- You need a GitHub account. A free account can run GitHub Actions within its usage allowance.
- Keep the repository **private**.
- The GitHub-hosted runner downloads npm packages and the Android toolchain, and compiles the app. Orbit Notes itself has no cloud account, sync, or sharing features.
- The app has **not yet been successfully compiled or tested on a physical Pixel 10**. A GitHub build can reveal errors that need fixing.

## Phone-only setup

1. On your Pixel 10, download and extract the project ZIP using Files.
2. In Chrome, open https://github.com/new and create a **Private** repository called `orbit-notes-android`. Leave the initialization options blank.
3. In the empty repository, choose **uploading an existing file** (or Add file > Upload files). Upload all project files in the extracted folder's top level, including `App.tsx`, `package.json`, `app.json`, `index.js`, `storage.ts`, etc. Upload the two `tests/` files into a `tests` folder. GitHub's mobile browser upload UI may require using Chrome's **Desktop site** mode. Do **not** upload the ZIP as a single file: GitHub will not automatically extract it into the repository.
4. Ensure `.github/workflows/android-apk.yml` exists in the repository. On mobile, the simplest fallback is **Add file > Create new file**, and enter `.github/workflows/android-apk.yml` as the filename; paste the contents from the workflow included in this ZIP. Commit the file to `main`.
5. Open the repository's **Actions** tab, select **Build Orbit Notes Android APK**, and tap **Run workflow**. The workflow also runs automatically when you push to `main`.
6. Wait for the job. If it turns green, open the run, scroll to **Artifacts**, and download **Orbit-Notes-Android-APK**. GitHub packages the APK inside a ZIP artifact.
7. In Pixel's Files app, extract the artifact ZIP and tap the `.apk` inside. If prompted, temporarily allow installation from Chrome or Files, then tap Install. Disable this permission again afterwards.

## Important limitations

- This GitHub Actions build uses Gradle's generated release configuration, which typically signs a prototype APK using the Android debug keystore generated by Expo prebuild. **This is for personal testing only, not Play Store distribution.** The signing key can change between builds; an APK signed with a different key cannot update the existing installation without uninstalling it. Uninstalling removes local app data. Test backup/restore before trusting it and avoid important notes.
- Android source project dependencies and Gradle build were **not** installed/run in the authoring environment. The GitHub workflow may fail, especially at `npm run typecheck` or Gradle compilation; a failed workflow does **not** produce an APK.
- The app's SQLite data is not independently encrypted at rest. Backup encryption has not been verified on-device.
- `android/` is generated on the GitHub runner and should not be uploaded to the repository.
- A long-term release process should use a stable signing key or EAS-managed signing credentials.

## What the workflow does

1. Checks out source, installs Node.js 22, Java 17 and Android SDK.
2. Runs `npm install`, source tests and TypeScript checks.
3. Runs `npx expo prebuild --platform android --clean --no-install`.
4. Runs `./gradlew assembleRelease` to create a standalone APK that does **not** require Expo Go or Metro.
5. Uploads the APK as a downloadable GitHub Actions artifact.
